# Market Sentinel v0.6.5 — UX & Daily Usability Polish

目标：

把当前已经跑通的 v0.6 核心能力，从“开发者可以用”提升到“日常使用时信息清楚、操作自然”。

本版本重点是：

```text
Intelligence 开关易用
Watchlist 易管理
股票显示更友好
StatusBar 更像行情状态栏
Hover 信息层次更清楚
AI 内容来源明确
Replay Demo 不误导
Alert telemetry 与 UI 一致
```

不是新增市场策略版本。

---

# 2. U0 — 先做一次 UI 数据能力审计

开始修改前先确认当前 Host / Wire 已经有哪些字段。

特别检查：

```text
symbol
current price
day change / previous close
feed status
scheduler level
active signals
alert candidates
intelligence status
intelligence summary
last market timestamp
```

回答：

1. 当前价格是否已经在 WireMarketState；
2. “当日涨跌幅”是否有真实字段；
3. 如果没有，当日涨跌幅缺的是：

   * Provider 数据；
   * Domain；
   * Wire；
   * Host；
4. Intelligence enriched summary 当前具体位于哪个 wire field；
5. Host 当前如何判断 aggregate feed state；
6. Replay EOF 当前为什么最终表现成 missing quote。

---

## 关于“当日涨跌幅”

绝对禁止把：

```text
1m change
5m change
```

冒充：

```text
当日涨跌幅
```

如果当前数据链没有真实：

```text
previous_close / session_change
```

则：

```text
先显示 --
```

或者通过最小 additive field 补真实数据。

不要制造近似值。

U0 完成后可以直接继续 U1，不需要停。

# 3. U1 — Intelligence 开关用户化

## 当前问题

现在用户需要：

```powershell
$env:MARKET_SENTINEL_INTEL_ENABLED="1"
```

这对普通使用非常不自然。

API Key 继续保留环境变量：

```text
DASHSCOPE_API_KEY
```

这是正确的。

但功能开关应该成为正常产品配置。

---

## 3.1 CLI

为：

```text
run
daemon
```

增加明确 CLI 开关。

推荐：

```bash
--intelligence
--no-intelligence
```

或者统一 enum：

```bash
--intelligence on
--intelligence off
```

优先选择项目 CLI 风格最一致的实现。

---

## 3.2 优先级

推荐：

```text
explicit CLI flag
>
MARKET_SENTINEL_INTEL_ENABLED env
>
default OFF
```

即：

```text
CLI 未指定
→ 兼容现有 env
```

这样不会破坏旧用户。

---

## 3.3 Cursor 设置

增加：

```text
marketSentinel.intelligence
```

建议 enum：

```text
off
on
inherit
```

推荐默认：

```text
off
```

或者为了最大兼容：

```text
inherit
```

由现有行为审计后决定。

Host spawn Core 时：

```text
on  → 传显式 CLI on
off → 传显式 CLI off
inherit → 不传，让 env 决定
```

不要把 API Key 写入 Cursor settings。

---

## 3.4 Key 缺失

如果：

```text
intelligence = on
```

但：

```text
DASHSCOPE_API_KEY missing
```

保持现有 fail-open：

```text
warning
→ Rule-only
```

不能打死 Core。

---

## 3.5 Hover 状态

Hover 顶部增加明确：

```text
AI：关闭
AI：已启用
AI：处理中
AI：已增强
AI：回退
```

不要让用户猜模型有没有运行。

# 4. U2 — 股票中文名与显示名

## 当前问题

现在 UI 只显示：

```text
00700.HK
600519.SH
```

用户体验较差。

目标：

```text
贵州茅台
腾讯控股
```

或者：

```text
贵州茅台 (600519.SH)
```

---

## 4.1 v0.6.5 不增加网络证券名称服务

本轮不要：

* 新接证券代码查询 API；
* 为了股票名再访问腾讯/新浪；
* 新增 provider 网络依赖；
* 增加全 A 股静态大数据库。

---

## 4.2 使用本地 Display Name / Alias

增加 Host setting，例如：

```json
"marketSentinel.symbolNames": {
  "600519.SH": "贵州茅台",
  "000001.SZ": "平安银行",
  "00700.HK": "腾讯控股"
}
```

名称只用于：

```text
UI display
```

不进入：

```text
Signal identity
Telemetry correlation
Watchlist identity
Provider symbol
```

真正 ID 永远还是：

```text
600519.SH
```

---

## 4.3 Fallback

如果没有配置 alias：

```text
显示 symbol code
```

不能因为名字不存在而影响行情。

---

## 4.4 Display mode

建议增加：

```text
marketSentinel.symbolDisplay
```

enum：

```text
name
nameAndCode
code
```

默认建议：

```text
nameAndCode
```

但：

### StatusBar

为了节省长度，可以优先：

```text

```

### Hover

优先：

```text
贵州茅台 (600519.SH)
```

# 6. U4 — StatusBar 重新设计

这是 v0.6.5 最重要的 UI 改进之一。

## 当前问题

现在：

```text
MS STALE
MS ALERT
```

更像诊断状态，而不像日常行情工具。

并且背景色占视觉注意力过多。

---

# 6.1 去掉背景色

StatusBar 不再使用明显：

```text
红色 / 黄色背景
```

用 icon 表达系统状态。

---

## 6.2 状态 icon

使用 VS Code ThemeIcon / Codicon。

概念映射：

```text
正常连接      ○ / circle
Starting      spinner
Paused        pause
Delayed       clock
Stale         warning
Disconnected  X / error
Alert         bell
```

具体 Codicon 名称按 VS Code 实际支持项选择。

不要使用 emoji。

---

# 6.3 StatusBar 主要内容改成行情

正常情况下优先显示：

```text
○ 贵州茅台 1412.30 +1.28% | 平安银行 12.34 -0.55%
```

而不是：

```text
MS NORMAL
```

如果当前有 3 个以上：

```text
○ 贵州茅台 1412.30 +1.28% | 平安银行 12.34 -0.55% | +3
```

---

## 默认最多显示

建议：

```text
2 symbols
```

避免 StatusBar 被 10 个 symbol 占满。

增加可选 setting：

```text
marketSentinel.statusBarMaxSymbols
```

例如：

```text
1–3
```

默认：

```text
2
```

---

## 6.4 Alert

有 unread alert：

```text
🔔 不使用 emoji
```

使用 Codicon：

```text
$(bell) 贵州茅台 1412.30 +1.28% · 2
```

其中：

```text
· 2
```

仍是 unread count。

---

## 6.5 Feed 异常

例如 disconnected：

```text
$(error) 贵州茅台 1412.30 +1.28%
```

不要把整个 StatusBar 变红。

具体：

```text
Feed: DISCONNECTED
```

放 Hover 中。

---

## 6.6 没有价格

例如刚启动：

```text
○ 贵州茅台 --
```

不能因为没有当前 tick 就不显示 Watchlist。

# 7. U5 — Hover 重新设计

## 核心目标

即使：

```text
没有 Event
没有 Signal
没有 Alert
```

Hover 也必须是有用的。

---

# 7.1 Hover 顶部状态

建议：

```text
Market Sentinel

连接：正常
行情源：LIVE
AI：已启用
未读提醒：0
最后更新：14:32:05
```

不要让：

```text
feed
AI
unread
```

混在一长行里。

---

# 7.2 没有 Signal 时

至少显示：

```text
贵州茅台 (600519.SH)
价格：1412.30
当日：+1.28%
状态：COLD
```

多个 symbol：

```text
贵州茅台 (600519.SH)
1412.30 · +1.28% · COLD

平安银行 (000001.SZ)
12.34 · -0.55% · WARM
```

---

# 7.3 有 Signal / Alert 时

不能再把所有信息挤在一个 paragraph。

改成明确 section。

推荐结构：

```text
贵州茅台 (600519.SH)
1412.30 · +1.28% · HOT

[IMPORTANT] ↑ price_volume

规则信号
价格与成交量同时扩大，并出现日内突破。

AI 增强
价格、成交量和突破事件在同一 episode 中收敛，
本次异动值得进一步关注。
AI 状态：已增强 · confidence 0.82

涨跌幅
1m +0.80% | 5m +0.80% | 15m +0.80%

成交
1m 9.00x | 5m 2.60x

技术指标
EMA5 100.00 | EMA20 100.00 | RSI14 50.0
VWAP 100.80 · 当前位于 VWAP 下方

日内区间
当前高 100.80 | 前高 100.40
当前低 100.00 | 前低 100.00

触发规则
day_high_breakout
price_volume_expansion
rapid_move
volume_spike
```

---

# 7.4 Rule 与 AI 必须明确分开

这是本轮 P0。

当前用户无法判断：

```text
哪一句是 deterministic rule
哪一句是 LLM
```

必须显示：

```text
规则信号
AI 增强
```

不要把 AI summary 无标签插在 Rule summary 后面。

---

## Intelligence 状态

如果：

```text
queued
running
```

显示：

```text
AI 增强：处理中…
```

如果：

```text
fallback
```

显示：

```text
AI 增强：本次未完成
```

可以显示固定低基数原因：

```text
timeout
provider_error
parse_error
```

不要直接显示 raw provider error text。

---

# 7.5 同类型周期指标放一行

用户反馈非常明确：

同类型不同周期应该同一行。

例如：

```text
涨跌幅：
1m +0.80% | 5m +0.80% | 15m +0.80%
```

```text
量比：
1m 9.00x | 5m 2.60x
```

不要：

```text
1m ...
5m ...
15m ...
```

占三行。

---

# 7.6 不同语义必须换行

必须分开的：

```text
价格变化
成交量
技术指标
VWAP
日内高低
触发规则
AI
```

目标是：

```text
扫一眼能看懂
```

不是把所有字段压成一段文字。

---

# 7.7 多 Signal

多个 active Signal 之间：

```text
---
```

分隔。

每个 Signal 只显示自己相关的：

```text
priority
direction
family
Rule
AI
rules
```

公共行情指标不要每个 Signal 重复十次。

最好采用：

```text
Symbol snapshot
↓
Signal 1
↓
Signal 2
```

结构。

# 8. U6 — Replay Demo 体验修复

这是本轮建议加入的第二个 UX 修复。

## 当前问题

Replay fixture 播完以后：

```text
ReplayProvider
→ missing quote
→ STALE
→ DISCONNECTED
→ 不断 WARNING
```

对 Demo 用户来说会误以为：

```text
程序坏了
```

但其实只是：

```text
Replay 播完
```

---

## 8.1 Replay EOF 必须与 live provider error 区分

不要继续把：

```text
Replay exhausted
```

解释成：

```text
provider failure
```

---

## 推荐语义

Replay 播完：

```text
REPLAY_COMPLETE
```

可以是：

* daemon lifecycle internal state；
* Host lifecycle display；
* additive optional Wire field；

具体实现按现有架构最小化。

不要为了这个创建 Protocol v2。

---

## 8.2 UI

StatusBar 可以：

```text
$(check) Replay 已结束
```

Hover：

```text
模式：Replay
状态：已播放完成
最后行情：10:02:00
```

保留最后一个有效 MarketState。

不要清掉：

```text
最后价格
HOT/WARM
最后 Signal
```

---

## 8.3 不刷 WARNING

Replay EOF 后不能不断：

```text
provider error: missing quote
```

真实 live provider 的 missing quote / timeout 行为保持不变。

---

## 8.4 本轮不做

不要加：

```text
Replay 5x
Replay 10x
Replay loop
Replay seek
```

这些留以后。

v0.6.5 只解决：

```text
EOF graceful completion
```

# 9. U7 — 修复 alert_presented telemetry 不一致

这是实际使用发现的 bug。

当前已观察到：

```text
UI:
Unread alerts = 1
```

但：

```text
telemetry report:
alerts_presented = 0
```

按合同这不应该发生。

---

## 9.1 先写复现测试

场景：

```text
Core sends unsolicited alert candidate
→ Host noteAlert()
→ unread += 1
→ host_interaction(alert_presented)
→ Core telemetry
```

最终：

```text
UI unread count > 0
```

必须对应：

```text
alert_presented >= 1
```

对于同一 candidate。

---

## 9.2 特别检查 Replay EOF race

可能场景：

```text
alert
→ Host unread increment
→ Replay quickly EOF / Core disconnect
→ host_interaction command 没来得及写回
```

需要确认并修复。

---

## 9.3 语义不变

仍然保持：

```text
alert_candidate != alert_presented
```

`alert_presented` 只有 Host 实际收到后产生。

不能简单在 Core：

```text
alert_candidate
→ 自动假装 alert_presented
```

# 13. 测试要求

## Intelligence

* CLI on overrides env off；
* CLI off overrides env on；
* inherit/fallback 正确；
* on + missing key → Rule-only，不崩；
* Host setting 正确转换 spawn args；
* Hover 不触发模型。

---

## Symbol display

* alias 存在 → 显示中文名；
* alias 不存在 → fallback code；
* symbol identity 不改变；
* telemetry 仍用 canonical symbol；
* name/code/nameAndCode 三模式。

---

## Watchlist

* Add；
* Remove；
* duplicate rejected；
* > 10 rejected；
* runtime set_watchlist 更新；
* 不要求 Core restart；
* Settings persistence 正确。

---

## StatusBar

* connected icon；
* delayed icon；
* stale/disconnected icon；
* alert icon；
* paused / starting；
* 无背景色；
* 0/1/2/3+ symbols；
* MaxSymbols；
* 没有 price 显示 `--`。

---

## Hover

* no signal；
* one signal；
* multiple signals；
* Rule 与 AI 分区；
* AI queued/running/enriched/fallback；
* grouped 1m/5m/15m；
* missing optional metrics；
* display name。

---

## Replay EOF

* EOF ≠ provider error；
* EOF 不刷 warning；
* EOF 不变 STALE/DISCONNECTED；
* 最后 MarketState 保留；
* live provider missing quote 语义不变。

---

## Telemetry

* unread alert → exactly one corresponding alert_presented；
* N candidates → N presented；
* Replay EOF race 不丢 presented；
* badge reset 不产生 dismissed；
* stdout 不污染。
