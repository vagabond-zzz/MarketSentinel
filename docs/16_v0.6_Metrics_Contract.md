## 1. Invariants

```text
measurement != mutation
feedback != market fact
telemetry != MarketState
storage schema != Wire Protocol
offline tuning != online self-modification
```

Forbidden:

```text
user dismisses alert  →  delete/modify historical Event
feedback says noisy   →  production threshold rewrites itself
LLM                   →  automatically tune Event/Scheduler rules
```

---

## 2. Audited current flow

```text
EventDetector.evaluate
        ↓ generated MarketEvent[]
EventDeduper.accept
        ↓ accepted | suppressed
SignalComposer.consume_batch
        ↓ new Signal.id  |  same id (upgrade / look-back join)
CooldownGate.allow
        ↓ alert_candidates (eligible reminders, not notified)
MarketEngine tick → Protocol unsolicited `alert`
        ↓
HostController increments unread (Host-local)
        ↓
resetAlertBadge clears unread count only
```

Facts today:

| Layer | What exists | What is missing |
|---|---|---|
| Event | Detector emits; deduper may drop same `dedupe_key` inside TTL | No counter for generated vs dropped |
| Cluster | Composer look-back `CLUSTER_LOOKBACK_S=90` groups into an episode | No `event_clustered` observation |
| Episode | New `uuid` vs reuse of active `(symbol, lineage, direction)` id | No created vs escalated counter |
| Alert candidate | Cooldown (default 300s monotonic) on `signal.id` | `notified_timestamp` still absent |
| Presented | Host unread += `alert.candidates.length`; toast optional | No per-alert presentation log |
| Opened | Hover/StatusBar inspect is not an explicit command | `signal_opened` not implemented |
| Dismiss | `resetAlertBadge` zeros the **count** | No per-`signal_id` dismiss |
| Mute | — | Placeholder only (M1) |
| Intelligence | `IntelligenceDiagnostics` process counters | No token_in/out; not a telemetry stream |

Intelligence diagnostics already count: `router_decisions`, `requests_submitted`, `requests_suppressed`, `model_calls`, `fallback_count`, timeouts/parse/rate-limit/backpressure/`stale_discard`, plus router/model/parse latency sums. They live on the coordinator, not in `MarketState` or Protocol.

## 3. Types

| Type | Role |
|---|---|
| `TelemetryEvent` | One append-only observation of pipeline / Host / intelligence |
| `UserFeedback` | Optional explicit Useful / Not Useful / Too Noisy / Too Late |
| `TuningSnapshot` | Versioned **offline** config identity. No `apply()` |

These are Core domain records under `market_sentinel.telemetry`. They are not `MarketState`, not `WireMarketState`, and not storage rows (M2).

## 4. Event taxonomy

| Name | Kind | Current producer (when wired in M1+) |
|---|---|---|
| `event_generated` | pipeline | `EventDetector.evaluate` each `MarketEvent` |
| `event_deduped` | pipeline | `EventDeduper.accept` returns `None` |
| `event_clustered` | pipeline | Accepted event composed into an episode with **more than one** `event_id` |
| `signal_episode_created` | pipeline | Composer allocates a new `Signal.id` |
| `signal_escalated` | pipeline | Same `Signal.id`, strictly higher `priority` |
| `alert_candidate` | pipeline | `CooldownGate.allow` is true |
| `alert_presented` | host | Host increments unread from unsolicited Protocol `alert` |
| `signal_opened` | host | **Not implemented.** Future explicit inspect (not automatic hover) |
| `alert_badge_reset` | host | `resetAlertBadge` (count only) |
| `alert_dismissed` | host | **Not implemented.** Per-candidate dismiss |
| `signal_muted` | host | **Not implemented.** M1 placeholder |
| `intelligence_routed` | intelligence | Router requested and work submitted |
| `intelligence_skipped` | intelligence | Router did not request (`requests_suppressed`) |
| `intelligence_succeeded` | intelligence | Registry status `enriched` |
| `intelligence_fallback` | intelligence | Registry status `fallback` |
| `intelligence_token_usage` | intelligence | **Unknown today.** Emit only if adapter reports usage |
| `intelligence_latency` | intelligence | Router / model / parse seconds already measured on diagnostics |

## 5. Field allowlist

`TelemetryEvent.to_record()` may only keep:

```text
telemetry_id, name, kind, created_timestamp,
symbol, event_id, signal_id, event_type, family, direction, priority,
host_action, intelligence_status, fallback_reason,
latency_s, token_in, token_out
```

`UserFeedback`: `feedback_id, created_timestamp, label, symbol, event_id, signal_id, telemetry_id`

`TuningSnapshot`: `snapshot_id, created_timestamp, source, config_version, notes`

`created_timestamp` must come from an injected Clock when producers exist (M1). M0 types do not call `time.time()`.

---

## 6. Privacy denylist

Never on telemetry/feedback/tuning records:

```text
workspace, source_code, conversation, files,
ticks, snapshots, ring_buffer, features,
prompt, api_key,
title, summary, reason,
event_ids, rule_names, priority_reason,
delete_event, rewrite_threshold, mutate_signal, apply_online
```

Also never: Cursor conversation, unrelated editor activity, unrelated local files.

Title/summary/intelligence `reason` are Market Sentinel copy but are **joined via `signal_id`**, not copied into the telemetry stream in M0.

---

## 7. Lifecycle

```text
observe (pipeline / Host / intelligence)
    → TelemetryEvent  (measurement only)
optional UserFeedback  (opinion, not a fact)
M2: append-only local log
M5: TuningSnapshot from Replay before/after
    → human applies a new config version offline
    → production rules do not rewrite themselves
```

Host interaction never writes “this Event never happened.”

---

## 8. Relationship to Event / Signal IDs

`event_id` and `signal_id` are **correlation keys** only.

- `telemetry_id` is distinct from `signal.id`
- Feedback may point at `signal_id` / `event_id` / `telemetry_id`
- Feedback must not delete, rewrite, or expire those objects

---

## 9. Relationship to Protocol

Protocol remains **v1**.

M0 does **not** add a `telemetry` JSONL type, Host command, or DTO.

Later Host feedback **may** become an additive Protocol command; that is a separate, versioned change. Storage schema (M2) is not the wire schema.

---

## 10. Relationship to persistent state

| State | Owner | Telemetry? |
|---|---|---|
| `MarketState` / active Signals | Core | No |
| Watchlist file | Core | No |
| Host unread count | Host memory (resets on reload) | Presentation; `alert_badge_reset` measures the **action** |
| Intelligence registry | Sidecar, keyed by `signal_id` | No; observations may *describe* status |
| Future JSONL/SQLite log | M2 | Yes, append-only |

Unread badge is not a telemetry database.

---

## 11. Relationship to Intelligence diagnostics

`IntelligenceDiagnostics.snapshot()` stays a **process-lifetime counter object**.

M1+ may *also* emit `TelemetryEvent`s at the same observation points. Counters are not replaced; they are not the audit log.

Token usage is **not** in diagnostics today. Do not invent token numbers. `intelligence_token_usage` is omitted until the adapter exposes usage.
