## 1. Invariants

```text
measurement != mutation
feedback != market fact
telemetry != MarketState
storage schema != Wire Protocol
offline tuning != online self-modification
```

Forbidden:

```text
user dismisses alert  →  delete/modify historical Event
feedback says noisy   →  production threshold rewrites itself
LLM                   →  automatically tune Event/Scheduler rules
```

## 2. Audited current flow

```text
EventDetector.evaluate
        ↓ generated MarketEvent[]
EventDeduper.accept
        ↓ accepted | suppressed
SignalComposer.consume_batch
        ↓ new Signal.id  |  same id (upgrade / look-back join)
CooldownGate.allow
        ↓ alert_candidates (eligible reminders, not notified)
MarketEngine tick → Protocol unsolicited `alert`
        ↓
HostController increments unread (Host-local)
        ↓
resetAlertBadge clears unread count only
```

Facts today:

| Layer | What exists | What is missing |
|---|---|---|
| Event | Detector emits; deduper may drop same `dedupe_key` inside TTL | No counter for generated vs dropped |
| Cluster | Composer look-back `CLUSTER_LOOKBACK_S=90` groups into an episode | No `event_clustered` observation (M1 membership tracker) |
| Episode | New `uuid` vs reuse of active `(symbol, lineage, direction)` id | No created vs escalated counter |
| Alert candidate | Cooldown (default 300s monotonic) on `signal.id` | `notified_timestamp` still absent |
| Presented | Host unread += `alert.candidates.length`; toast optional | No per-candidate presentation log |
| Opened | Hover/StatusBar inspect is not an explicit command | `signal_opened` not implemented |
| Dismiss | `resetAlertBadge` zeros the **count** | No per-`signal_id` dismiss |
| Mute | — | Placeholder only (M1) |
| Intelligence | `IntelligenceDiagnostics` process counters | No token_in/out; not a telemetry stream |

Intelligence diagnostics already count: `router_decisions`, `requests_submitted`, `requests_suppressed`, `model_calls`, `fallback_count`, timeouts/parse/rate-limit/backpressure/`stale_discard`, plus router/model/parse latency sums. They live on the coordinator, not in `MarketState` or Protocol. Telemetry does **not** replace these counters.

## 3. Types

| Type | Role |
|---|---|
| `TelemetryEvent` | One append-only observation of pipeline / Host / intelligence |
| `UserFeedback` | Optional explicit Useful / Not Useful / Too Noisy / Too Late |
| `TuningSnapshot` | Versioned **offline** config identity. No `apply()`. No free-text `notes` |

These are Core domain records under `market_sentinel.telemetry`. They are not `MarketState`, not `WireMarketState`, and not JSONL storage rows. Storage serializes `TelemetryEvent.to_record()` only.

## 4. Ownership (Host vs Core)

```text
Host interaction fact owner:  Host
Telemetry collector / future local storage owner:  Core
```

Constants in `market_sentinel.telemetry.contract`:

```text
HOST_INTERACTION_FACT_OWNER = "host"
TELEMETRY_COLLECTOR_OWNER = "core"
```

M1 path (additive Protocol v1 host-interaction command):

```text
Cursor Host
  → additive Protocol v1 `host_interaction`
  → Core telemetry collector
  → optional JSONL sink (M2)
```

Not:

```text
Python pipeline telemetry DB
+
independent Cursor telemetry DB
```

Host storage schema is **not** the Protocol schema. Protocol remains **v1**. `host_interaction` is additive. JSONL rows are not Protocol messages.

Core may emit pipeline and intelligence observations. Core **cannot** emit `alert_presented`: it only has `alert_candidate`. Host is the producer of presentation/unread facts. Core collects those facts and may persist them.

## 6. Field allowlist

`TelemetryEvent.to_record()` may only keep:

```text
telemetry_id, name, kind, created_timestamp, run_id, market_timestamp,
symbol, event_id, signal_id, event_type, family, direction, priority,
host_action, intelligence_status,
decision_reason, fallback_reason, suppression_reason,
latency_s, latency_stage, token_in, token_out
```

`UserFeedback`: `feedback_id, created_timestamp, run_id, label, symbol, event_id, signal_id, telemetry_id`

`TuningSnapshot`: `snapshot_id, created_timestamp, source, config_version`

There is **no** `notes` field and **no** free-text substitute. Human explanation of a tuning change belongs in an evaluation report / docs (M5), not in the telemetry/tuning storage contract.

There is **no** telemetry `session_id`. Trading-session grouping uses `market_sentinel.market_data.session.session_id(market_timestamp)` (UTC+8 market-date). Do not invent a second, differently meaning `session_id` on telemetry records.

M0 froze fields. M1 emits them at producer boundaries. M2 persists `to_record()` only.

## 7. Time and runtime correlation

### `created_timestamp`

Observation wall-clock time (when the record was created). Comes from the injected Clock on `TelemetryRuntime`. Must be finite.

### `market_timestamp`

Market time. Must not be mixed with `created_timestamp`.

| Kind of observation | Source |
|---|---|
| pipeline Event (`event_generated` / `event_deduped` / `event_clustered`) | `MarketEvent.market_timestamp` |
| Signal / alert (`signal_*`, `alert_candidate`, `alert_suppressed`) | `Signal.market_timestamp` |
| Intelligence (`intelligence_*`) | associated Signal market timestamp |
| Host-only interaction | may be `None`; join via `signal_id` |

### `run_id`

```text
one Core runtime / Replay execution
```

Required, non-empty, on both `TelemetryEvent` and `UserFeedback`.

Market trading session is **derived** from `market_timestamp` via existing `session.session_id()`. It is not a telemetry field.

This supports Replay evaluation, alerts-per-market-hour, daily/session summary, and old-config vs new-config comparison without a second `session_id`.

## 8. `event_clustered` (once per event per run)

Frozen semantics:

```text
event_clustered
= one event_id is observed the first time it participates in
  a multi-event Signal episode
```

Examples:

```text
new episode {e1,e2}
  → event_clustered(e1)
  → event_clustered(e2)

episode {e1}
later becomes {e1,e2}
  → e1 first becomes clustered
  → e2 first becomes clustered
  → emit for both

later {e1,e2,e3}
  → only e3 is newly clustered
```

Rule:

```text
one event_id  →  at most one event_clustered per run
```

Do not count Composer recomputes as additional clusters. Do not change Event / Signal identity for telemetry.

M0 froze the rule and ships `ClusterMembershipTracker`. M1 uses it as observe-only instrumentation.

## 9. Alert presentation vs suppression

### `alert_presented`

```text
alert_presented
= Host successfully receives one unsolicited alert candidate
  and incorporates it into Host presentation/unread state
```

One record **per candidate**. Core only has `alert_candidate` and cannot claim `alert_presented`. Host is the fact producer.

```text
alert_presented  !=  toast shown
```

Toast is an optional presentation style and is **not** counted separately in this round.

`signal_opened` remains an **explicit** command. Hover must not count as open.

`alert_badge_reset` is the current global unread-count action and stays separate from future per-id `alert_dismissed`.

### `alert_suppressed`

```text
Signal produced
  → alert edge intentionally not emitted
  → alert_suppressed
```

Kind: `pipeline`. Requires `SuppressionReason` (enum, not free text). M0 freezes:

```text
cooldown
same_tick_duplicate
```

This is **not** `event_deduped` (Event-level suppression). M3/M5 must be able to distinguish:

```text
few Events
vs
few Signals
vs
many cooldown suppressions
```

## 10. Intelligence skip vs fallback vs latency

```text
decision_reason  = Router NO  (deterministic)
fallback_reason  = provider/model completion failure
```

Do **not** put skip reasons into `fallback_reason`.

`DecisionReason` (low cardinality):

```text
expired_episode
suppressed_edge
stale_feed
insufficient_features
not_candidate
episode_budget
```

`intelligence_skipped` requires `decision_reason` and must not set `fallback_reason`.

`intelligence_fallback` requires `fallback_reason` and must not set `decision_reason`.

### Latency

`LatencyStage`: `router` | `model` | `parse`

`intelligence_latency` requires `signal_id` + `latency_s` + `latency_stage`.

`latency_s >= 0`.

### Tokens

`intelligence_token_usage` requires `signal_id` plus actual adapter `token_in` and/or `token_out` (`>= 0`).

Do **not** require token fields on every intelligence event. If the adapter has no usage, **do not emit** `intelligence_token_usage`. Never invent DashScope tokens.

## 11. Privacy denylist

Never on telemetry/feedback/tuning records:

```text
workspace, source_code, conversation, files,
ticks, snapshots, ring_buffer, features,
prompt, api_key,
title, summary, reason, notes,
session_id,
event_ids, rule_names, priority_reason,
delete_event, rewrite_threshold, mutate_signal, apply_online
```

Also never: Cursor conversation, unrelated editor activity, unrelated local files.

Title/summary/intelligence `reason` are Market Sentinel copy but are **joined via `signal_id`**, not copied into the telemetry stream in M0.

`notes` is denied so it cannot bypass key-level privacy as a “legal” TuningSnapshot field.

## 22. M2 JSONL storage

v0.6 MVP uses append-only JSONL, not SQLite.

```text
producer → TelemetryRuntime.emit → FailOpenTelemetryCollector
         → SinkTelemetryCollector (to_record only)
         → JsonlTelemetrySink
```

Pipeline, intelligence, and Host command handlers must not import `JsonlTelemetrySink`. CLI/factory owns the sink. Default Engine tests still use NoOp/InMemory.

### Path

Not the repo, not workspace source, not Cursor conversation data, not cwd.

| Source | Directory |
|---|---|
| `MARKET_SENTINEL_DATA_DIR` | override (tests inject a temp dir) |
| Windows | `%LOCALAPPDATA%/MarketSentinel` |
| Unix | `$XDG_DATA_HOME/market-sentinel` or `~/.local/share/market-sentinel` |

Files:

```text
telemetry.jsonl          # M2
telemetry.jsonl.1 … N    # rotated backups
feedback.jsonl           # reserved; M2 does not write it
```

### Serialization

Only `TelemetryEvent.to_record()` / `project_allowlist(..., TELEMETRY_ALLOWLIST)`. Never `json.dumps(event.__dict__)`. UTF-8, one JSON object plus newline per line. `ensure_ascii=False`.

### Lifecycle

`open` (repair trailing partial) → `append` + `flush` → `rotate` when size ≥ `max_bytes` → `close`. Defaults: `max_bytes=1048576`, `backup_count=5`. History is not rewritten on badge reset / feedback / tuning. No compression or upload.

### Corruption

- Trailing incomplete last line: reader skips it; next open truncates it.
- Valid JSON missing a newline: next open appends a newline.
- Complete malformed line in the middle: `malformed_complete_lines` increments; `healthy` is False; file is not silently rewritten.

Storage diagnostics use the logger, never the telemetry stream (no write loop). Errors go to stderr/logger. JSONL telemetry is not Protocol stdout.
