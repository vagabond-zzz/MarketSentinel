## 4. Final UX scope

v0.6.5 is a daily-usability release on top of v0.6.0.

### 4.1 StatusBar

- quote-focused text;
- Codicons instead of colored warning/error backgrounds;
- not `MS NORMAL` / `MS STALE` as the primary text;
- configurable number of symbols through `marketSentinel.statusBarMaxSymbols`;
- local display aliases via `marketSentinel.symbolNames`;
- `symbolDisplay` controls code/name presentation.

Status priority after host lifecycle remains:

```text
real feed STALE / DISCONNECTED
→ ALERT hold
→ replay_complete
→ DELAYED
→ HOT / WARM / NORMAL
```

### 4.2 Short Hover

The StatusBar Hover is intentionally short and optimized for quick scanning.

It contains the high-value snapshot only, rather than the complete long-form diagnostics / metrics document.

This avoids the original usability problem where a long native tooltip disappeared when the pointer moved and could not be practically scrolled.

### 4.3 Persistent details Webview

Clicking the Market Sentinel StatusBar, or invoking:

```text
Market Sentinel: Show Details
```

opens a dedicated persistent editor Webview:

```text
Market Sentinel · 行情详情
```

The details panel:

- remains open after the mouse leaves the StatusBar;
- is vertically scrollable;
- can display multiple symbols as responsive cards;
- refreshes from the latest Host state;
- preserves the current scroll position on refresh on a best-effort basis;
- renders Rule Signal and AI enrichment as separate sections;
- groups change, volume, technical indicators, VWAP and session-range information;
- does not replace `Market Sentinel: Show Output`.

`Market Sentinel: Show Output` remains the Core / Host diagnostic log.

The Webview:

- does not load external network resources;
- uses Content Security Policy;
- HTML-escapes user-visible alias / Rule / AI text;
- does not alter canonical symbol identity;
- does not add a new network service;
- does not change Core / Domain / Signal semantics.

Cursor setting:

| Setting | Spawn behavior |
|---|---|
| `on` | `--intelligence` |

## 8. Replay EOF semantics

`source_exhausted()` is checked before `fetch_quotes()`.

Only an already-exhausted Replay source may keep the last healthy quote alive without creating a missing-quote observation.

`keep_alive` updates freshness only when `consecutive_failures == 0`.

Therefore:

- normal Replay EOF does not create a missing-quote storm;
- the last valid price / market state / Signal remain visible;
- a real last-batch missing symbol still takes the missing-quote path;
- the next fetch may then transition to graceful EOF;
- live provider missing-quote behavior is unchanged.

If the final tick presented an alert:

```text
ALERT hold (~15s)
→ Replay 已结束
```

The final UX polish does not change these Core semantics.
