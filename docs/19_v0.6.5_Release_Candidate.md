## 3. v0.6.5 最终功能范围

### 3.1 StatusBar

StatusBar 以行情为主，不再把 `MS NORMAL` / `MS STALE` 作为主要文本，也不使用整条红黄背景色。

典型呈现：

```text
$(circle-outline) 贵州茅台 1412.30 +1.28% | 平安银行 12.34 -0.55%
```

支持：

- Codicon 状态；
- 中文 alias；
- `name` / `nameAndCode` / `code`；
- 最多展示 1–3 个 symbol；
- unread alert badge；
- Replay 完成状态。

Host 状态优先级保持：

```text
STARTING / DISCONNECTED / PAUSED
→ real feed STALE / DISCONNECTED
→ ALERT hold
→ Replay complete
→ DELAYED
→ HOT / WARM / NORMAL
```

### 3.2 Short Hover

原生 StatusBar Hover 改为快速摘要，不再承载过长、无法滚动的完整内容。

Hover 主要用于查看：

- connection / feed / AI；
- unread；
- 最后行情时间（UTC+8）；
- symbol、价格、当日涨跌幅；
- COLD / WARM / HOT。

Hover 不触发 Intelligence，也不生成 feedback。

### 3.3 可滚动 Details Webview

点击 Market Sentinel StatusBar，或运行：

```text
Market Sentinel: Show Details
```

打开：

```text
Market Sentinel · 行情详情
```

Details Webview：

- 持久存在，不因鼠标移开而消失；
- 支持垂直滚动；
- 支持多股票卡片布局；
- 展示完整行情、Rule Signal、AI 增强和指标；
- Core 状态更新时刷新；
- 刷新时 best-effort 保持滚动位置；
- 不加载外部网络资源；
- 使用 CSP；
- alias / Rule / AI 文本进行 HTML escaping。

`Market Sentinel: Show Output` 继续只用于 Core / Host 日志。

### 3.4 Watchlist Commands

Command Palette 支持：

```text
Market Sentinel: Add Symbol
Market Sentinel: Remove Symbol
Market Sentinel: Manage Watchlist
```

Host 持久化 `{symbol, enabled}` 到 Workspace `marketSentinel.watchlist`，成功的 runtime `set_watchlist` 不需要 Restart Core。

Cursor Host Watchlist 与 CLI `data/watchlist.json` 仍是两个独立入口，不自动双向同步。

### 3.5 Intelligence 开关

优先级：

```text
显式 CLI --intelligence / --no-intelligence
> MARKET_SENTINEL_INTEL_ENABLED
> Core 默认关闭
```

Cursor：

| Setting | Spawn |
|---|---|
| `on` | `--intelligence` |
| `off` | `--no-intelligence` |
| `inherit` | 不传 flag |

API Key 仍只从环境变量读取：

```text
DASHSCOPE_API_KEY
```

设置不保存 secret；live DashScope 不作为默认 release gate。

### 3.6 Replay EOF

Replay exhausted 后：

- 不再持续产生 missing-quote warning；
- 保留最后 price / state / Signal；
- 不伪造成 live provider failure；
- 最后一批真实缺 symbol 仍先走 missing-quote；
- 下一次 fetch 才进入 graceful EOF。

如果最后 tick 有 Alert：

```text
ALERT hold (~15s)
→ Replay 已结束
```

### 3.7 `alert_presented` 生命周期

Host presentation queue 捕获 origin IPC、manager generation 和 presentation timestamp。

目标：

- graceful teardown 尽量 flush；
- hard Core crash 仍是 best-effort；
- 不跨 Core generation 错记 telemetry。

### Privacy

保持以下边界：

- `DASHSCOPE_API_KEY` / `LONGBRIDGE_*` 仅来自环境变量；
- Cursor setting 不保存 secret；
- aliases 只影响 UI；
- AI summary 不新增 telemetry free-text 持久化；
- Webview 不请求外部资源；
- Webview 使用 CSP 和 HTML escaping；
- tracked tree 不应包含 `.env`、真实 key、JSONL runtime data、tuning snapshots、review archive 或 VSIX。

### Market semantics

相对 v0.6.0 base，以下核心策略仍未因最终 UX polish 改变：

```text
Event thresholds
Signal rules
Signal priority
Scheduler thresholds
cooldown / dwell
Intelligence Router policy
episode call budget
production tuning application
```

最终 `7d3b80b` 相对 Release Prep `7228e38` 的 Python production delta 仅涉及 Replay / tuning demo symbol 的 A 股化；Details / Hover 为 Host UI 层变化。

## 9. Known Limitations

- Watchlist 最多 10 个 symbol。
- Cursor Host 与 CLI Watchlist 不同步。
- Python Core 不打包进 VSIX。
- Symbol name 是本地 alias，没有联网 security-master lookup。
- Details Webview 只展示当前快照，不是完整 Alert history / charting terminal。
- Webview refresh 的滚动位置保持是 best-effort。
- unread badge 是 Host-local，extension reload 后会重置。
- `signal_opened` / `alert_dismissed` / `signal_muted` producer 尚未实现。
- Live DashScope 不在默认 gates 中。
- Tencent / Sina 仍是 probes，不是正式 Core provider wiring。
- JSONL 仍同步写入。
- Tuning Replay 的 monotonic time 仍固定，cooldown / dwell 等参数暂不进入 tuning candidate。
- 只有 7 个 evidence-backed Offline Tuning 参数。
- 尚未接入完整交易所节假日日历。
- 无 Marketplace / remote publication。
