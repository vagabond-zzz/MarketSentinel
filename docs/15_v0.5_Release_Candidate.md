## 6. Router rules

Skip (no call): expired episode; cooldown/duplicate edge (`alert_edge=False`); STALE/DISCONNECTED; missing `change_1m`+`change_5m`+`volume_ratio_5m`; INFO; ordinary NOTICE; episode budget exhausted.

Candidate: priority IMPORTANT or CRITICAL; or price+volume+breakout cluster (or ≥3 event types with price and volume).

DELAYED feed may still be a candidate. Policy is `RouterPolicy`, not the model.

## 7. Episode call budget

`EpisodeCallBudget(max_calls=1, allow_escalation_recall=False)`.

A later CRITICAL upgrade does **not** get a second call unless `allow_escalation_recall=True`.

Budget is consumed when work is **queued**, so repeats of the same `signal.id` do not enqueue again.

## 8. Async / queue / cancellation

- `asyncio.Queue(maxsize=8)`, concurrency 1
- `put_nowait`; full queue drops work (`dropped_backpressure`) and does not block tick
- `asyncio.wait_for(..., timeout_s)` around `provider.complete`
- Episode retirement bumps generation, prunes the registry, and best-effort cancels the in-flight task
- Queued stale work is discarded **before** `provider.complete` (`stale_discard`, `model_calls` unchanged)
- In-flight stale work: cancel is best-effort; if a result still arrives it is discarded and must not resurrect the registry
- `shutdown()` cancels workers and in-flight tasks, detaches the queue, and resets episode runtime maps (`_calls` / `_generation` / `_pending` / registry / `_active_ids`). Diagnostics counters are kept. Restart after shutdown is not polluted by the previous call budget.
- Already-issued HTTP may still consume tokens; we do not claim Token = 0 for that case. Completions must not reattach after shutdown.
- daemon `run()` and CLI `run` start/stop the sidecar
- Default daemon does not construct a coordinator unless `MARKET_SENTINEL_INTEL_ENABLED` is set
- Missing key / unknown provider: sidecar disabled, Core continues

## 18. Known limitations / UNKNOWN / PENDING

- Default daemon/CLI does not call a model (must set `MARKET_SENTINEL_INTEL_ENABLED`)
- Intelligence config failure disables the sidecar; Core stays Rule-only (no strict-fail mode in v0.5)
- Live DashScope non-thinking one-shot smoke **PASSED** at the production **8s** default (`enable_thinking: false`; three consecutive calls ~3.5–4.4s). Default pytest still does **not** call DashScope.
- Pre-release discovery (do not use as the non-thinking timeout baseline): when thinking was left implicit, live completions were ~25.8s to >30s. See Release Prep.
- Queue-full backpressure is counted but rarely hit at watchlist size 10
- Parse latency is recorded when the DashScope adapter runs parse; Fake reports 0
- Trading-instruction parse is fail-closed for listed EN/ZH phrases; bare `long`/`short` are only matched in collocations (`go long`, `long position`) to avoid `long-term` / `short-term`. Not all natural-language trading advice can be semantically detected.
- In-flight HTTP that the transport cannot abort may still consume tokens after episode retirement. Do **not** claim HTTP is always cancellable or that in-flight work always costs zero tokens.
- DashScope HTTP error-path coverage is partial by design
- CLI `--once` with fake provider often has no IMPORTANT episode; idle still drains any queued work
- Tencent is **not** a production `MarketProvider`. Full v0.4 live Provider → Core → Cursor is **not** closed. **v0.4.0 was not released.**
