## 2. Current Provider → Core contract (frozen)

**Do not change any of the following to fit Longbridge:** `MarketSnapshot.volume` semantics, Feature math, volume ratio math, VWAP math, Event thresholds, Scheduler, Feed Health, Protocol v1.

### 2.1 Provider Protocol

`MarketProvider` is a Python `Protocol` with one method:

```text
async fetch_quotes(symbols: list[str]) -> list[MarketSnapshot]
```

Defined in `src/market_sentinel/providers/base.py`.

Documented behavior in the Protocol docstring: **partial results are allowed**.

Current implementations:

| Provider | Role |
|---|---|
| `FakeProvider` | In-memory quotes; can omit a symbol, raise `TimeoutError`, or drop invalid rows |
| `ReplayProvider` | JSONL batches via `normalize_many` |

CLI already has `--provider http`, but it **exits 2** with “HttpQuoteProvider is not implemented”. Cursor settings enum is `fake` / `replay` only. `pyproject.toml` already lists optional extra `live = ["httpx>=0.27"]`; **nothing in Core uses it**.

### 2.2 Frozen `MarketSnapshot`

From `src/market_sentinel/domain/models.py`:

```text
MarketSnapshot.volume
  = session-cumulative share/lot count
    from session open through market_timestamp

MarketSnapshot.turnover
  = session-cumulative notional in the same session, or None

market_timestamp  ≠  received_timestamp
```

`received_timestamp` is **always** assigned by `normalize_snapshot()` as `clock.wall_time()`. Providers must not treat local receive time as market time.

Required raw fields for `normalize_snapshot()`:

```text
symbol, price, open, high, low, prev_close, volume, market_timestamp
```

`turnover` is optional (`None` if omitted). `price` must be `> 0`. `volume` / `turnover` must be finite and `>= 0`.

Symbol regex (Core, not vendor — **unchanged**):

```text
^[0-9A-Za-z]+\.(SH|SZ|HK)$
```

Core still accepts `.HK` for Fake/Replay and existing tests. **v0.4 live provider acceptance symbols are SH/SZ only.**

v0.4 live primary symbols:

```text
600519.SH
000001.SZ
```

These already match both Core regex and Longbridge `ticker.region` (no pad/map for A-shares).

Session key remains **UTC+8 calendar date** (`market_data/session.py`). v0.4 does not replace this with a global exchange calendar.

### 2.3 Engine failure semantics (already implemented)

`MarketEngine._fetch_due`:

| Provider outcome | Core behavior |
|---|---|
| `fetch_quotes` raises | log; `health.observe(..., error=exc)` per due symbol; **no snapshot appended**; Feature/Event **not** re-run for those symbols this tick |
| Symbol missing from returned list | `health.observe(..., error=RuntimeError("missing quote"))`; **no forged snapshot** |
| Valid snapshot | append buffer, update latest, `health.observe(symbol, snapshot)`, then Feature/Event |

This already matches the v0.4 hard rule: **failure ≠ reconstruct an old snapshot**.

Feed Health (`HealthPolicy` defaults, **not changed in M0 / M1a**):

```text
DELAYED  if (received - market) >= 3s
STALE    if last success age >= 30s
DISCONNECTED if age >= 60s or consecutive_failures >= 3
```

A successful quote whose `market_timestamp` is stale relative to receive time classifies as **DELAYED**. That is Core-correct. Do not write `datetime.now()` into `market_timestamp`. (HK BMP delay is **not** a v0.4 blocker; see §6.1 future notes.)

Scheduler intervals (relevant to rate limits):

```text
COLD 10s / WARM 3s / HOT 1s
watchlist limit 10
```

`fetch_quotes` is already a **batch** of due symbols.

### 2.4 Why volume/turnover semantics cannot be bent

Feature engine derives:

- `volume_1m` / `volume_5m` as **deltas of session-cumulative volume** (`latest.volume - anchor.volume`)
- `volume_ratio_*` as **dimensionless** current-window delta / historical average of the same deltas
- VWAP as `turnover / volume` when `turnover is not None` and `volume > 0`

**Volume delta / ratio** only require that `MarketSnapshot.volume` is a consistent cumulative series in **one** unit. They do not need the adapter to know whether that unit is 股 or 手, *provided the unit never changes mid-session*.

**VWAP** additionally requires `turnover` and `volume` to be **commensurate** (notional / quantity ≈ price). If that relationship is unconfirmed, **`turnover = None` is allowed** and VWAP stays off. **Forbidden:** `price * volume` as fake turnover.

If a live source supplies per-tick or per-bar volume, Event rules (`volume_spike`, `price_volume_expansion`, `vwap_cross`) become false positives. **Do not change Core math to match a vendor field.**

Ring buffer: same `market_timestamp` **replaces** the previous snapshot; older timestamps are inserted in order. v0.4 M3 still needs an explicit out-of-order policy; M0/M1a do not implement it.

### 2.5 Protocol v1 (Host)

Cursor consumes `state` / `alert` JSONL. Wire DTO has no provider fields, no API keys, no raw vendor quotes. `PROTOCOL_VERSION = 1`.

| Field | Official text |
|---|---|

## 20. Recommendation reasons (updated ranking)

A/H coverage is **not** a selection criterion.

1. **MarketSnapshot semantic correctness** — Pull quote exposes last, prev_close, open, high, low, volume, turnover, timestamp in one object. Push documents cumulative vs increment. Residual A-share unit/session-reset UNKNOWN (R2/R3) → **M1a**, not assumed away.
2. **Market timestamp reliability** — Official “time of latest price” + Unix UTC. Not `datetime.now()`.
3. **Cumulative volume reliability** — Better documented split than Futu (“units may differ”) and than mixing Tushare 手/股 APIs; A-share unit still UNKNOWN.
4. **A-share SH/SZ coverage** — Official `600519.SH` / `000001.SZ`; Core-compatible; CN LV1 in Basic.
5. **Rate-limit suitability** — 10/s batch of 500 ≫ ≤10 HOT. Tushare 50/min fails HOT.
6. **Failure semantics** — Documented rate-limit and server codes; Engine already omits snapshots.
7. **Testability** — Isolated probe + later recorded fixtures; Futu requires OpenD.
8. **Credential complexity** — Env vars; no local GUI daemon.
9. **Implementation complexity** — SDK wrap, no SH/SZ symbol pad, no OpenD, no second Tushare product.

“Easiest HTTP” would be Tushare `rt_k`. It **loses** on (1)(2)(5).
