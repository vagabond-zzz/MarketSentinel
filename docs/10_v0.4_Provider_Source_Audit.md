## 2. Current Provider → Core contract (frozen)

### 2.1 Provider Protocol

`MarketProvider` is a Python `Protocol` with one method:

```text
async fetch_quotes(symbols: list[str]) -> list[MarketSnapshot]
```

Defined in `src/market_sentinel/providers/base.py`.

Documented behavior in the Protocol docstring: **partial results are allowed**.

Current implementations:

| Provider | Role |
|---|---|
| `FakeProvider` | In-memory quotes; can omit a symbol, raise `TimeoutError`, or drop invalid rows |
| `ReplayProvider` | JSONL batches via `normalize_many` |

CLI already has `--provider http`, but it **exits 2** with “HttpQuoteProvider is not implemented”. Cursor settings enum is `fake` / `replay` only. `pyproject.toml` already lists optional extra `live = ["httpx>=0.27"]`; **nothing in Core uses it**.

### 2.2 Frozen `MarketSnapshot`

From `src/market_sentinel/domain/models.py`:

```text
MarketSnapshot.volume
  = session-cumulative share/lot count
    from session open through market_timestamp

MarketSnapshot.turnover
  = session-cumulative notional in the same session, or None

market_timestamp  ≠  received_timestamp
```

`received_timestamp` is **always** assigned by `normalize_snapshot()` as `clock.wall_time()`. Providers must not treat local receive time as market time.

Required raw fields for `normalize_snapshot()`:

```text
symbol, price, open, high, low, prev_close, volume, market_timestamp
```

`turnover` is optional (`None` if omitted). `price` must be `> 0`. `volume` / `turnover` must be finite and `>= 0`.

Symbol regex (Core, not vendor):

```text
^[0-9A-Za-z]+\.(SH|SZ|HK)$
```

Project test / product symbol: **`00700.HK`**. Session key for A/H MVP is **UTC+8 calendar date** (`market_data/session.py`). v0.4 does not replace this with a global exchange calendar.

### 2.3 Engine failure semantics (already implemented)

`MarketEngine._fetch_due`:

| Provider outcome | Core behavior |
|---|---|
| `fetch_quotes` raises | log; `health.observe(..., error=exc)` per due symbol; **no snapshot appended**; Feature/Event **not** re-run for those symbols this tick |
| Symbol missing from returned list | `health.observe(..., error=RuntimeError("missing quote"))`; **no forged snapshot** |
| Valid snapshot | append buffer, update latest, `health.observe(symbol, snapshot)`, then Feature/Event |

This already matches the v0.4 hard rule: **failure ≠ reconstruct an old snapshot**.

Feed Health (`HealthPolicy` defaults, **not changed in M0**):

```text
DELAYED  if (received - market) >= 3s
STALE    if last success age >= 30s
DISCONNECTED if age >= 60s or consecutive_failures >= 3
```

Implication for delayed vendor feeds (e.g. HK BMP ~15 min): a *successful* quote with a 15-minute-old `market_timestamp` will classify as **DELAYED**, not LIVE. That is Core-correct. Do not “fix” it by writing `datetime.now()` into `market_timestamp`.

Scheduler intervals (relevant to rate limits):

```text
COLD 10s / WARM 3s / HOT 1s
watchlist limit 10
```

`fetch_quotes` is already a **batch** of due symbols (not 10 independent single-symbol HTTP calls unless the adapter chooses that).

### 2.4 Why volume/turnover semantics cannot be bent

Feature engine derives:

- `volume_1m` / `volume_5m` as **deltas of session-cumulative volume**
- VWAP as `turnover / volume` when `turnover is not None` and `volume > 0`

If a live source supplies per-tick or per-bar volume, or lot vs share mismatch vs turnover currency units, Event rules (`volume_spike`, `price_volume_expansion`, `vwap_cross`) become false positives. **Do not change Core math to match a vendor field.**

Ring buffer: same `market_timestamp` **replaces** the previous snapshot; older timestamps are inserted in order (no rewind of Event state beyond existing buffer/event logic). v0.4 M3 still needs an explicit out-of-order policy at the live-adapter or engine boundary; M0 does not implement it.

### 2.5 Protocol v1 (Host)

Cursor consumes `state` / `alert` JSONL. Wire DTO has no provider fields, no API keys, no raw vendor quotes. `PROTOCOL_VERSION = 1`.

## 10. Volume semantics (M0 critical)

Core: **session cumulative**.

### Longbridge

Pull `SecurityQuote.volume`: official description is the single word **“Volume”** (int64). **Unit (shares vs lots vs 手): UNKNOWN.**

Push distinguishes:

| Field | Official text |
|---|---|
| `volume` | Volume |
| `current_volume` | **Increase volume between pushes** |
| `turnover` | Turnover |
| `current_turnover` | **Increase turnover between pushes** |

So `volume` is **not** the inter-push increment. That supports “running total” vs “this push’s delta”. Whether the running total is **session** vs **calendar day** vs **including US pre-market**: **UNKNOWN**. Session reset: **UNKNOWN**.

Static API documents `lot_size` separately from quote `volume`. Official docs **do not** say quote volume is in lots. **Do not multiply by `lot_size` unless a later official note or a measured consistency test (M1) proves it.**

**M0 does not assume Longbridge volume can be copied into `MarketSnapshot.volume` as shares.** M1 must verify (recorded + optional live): order-of-magnitude vs `lot_size` and `turnover / volume ≈ last_done`. If that check fails, keep `turnover=None` and/or refuse to enable VWAP — **do not** invent `price * volume`.

### Futu

Get quote / snapshot: `volume` = **“Volume”**. Open API data-format: **“Units may differ across markets; display according to market rules.”**

Session vs tick vs bar: **UNKNOWN**.

This is a **harder** unit problem than Longbridge’s increment/total split.

### Tushare (official units — do not mix APIs)

| API | Official `vol` unit |
|---|---|
| `daily` (historical A-share) | **手** |
| `rt_k` (realtime A-share daily k) | **股** |
| `rt_hk_k` | **股** |
| `stk_mins` | **股** (per **minute bar**, not session cumulative of the day unless summed) |

`rt_k.vol` as 股 on an updating daily bar is the closest **documented session-to-date cumulative** among Tushare APIs. It is still a **bar snapshot**, not a last-sale quote. Mixing `daily` (手) with `rt_k` (股) would break Core.

| Code | Official meaning | Planned Core mapping (M1, not implemented) |

| 301600 | Invalid request / unpack fail | no snapshot; transport/parse error |
| 301606 | Request rate limit | no snapshot; rate-limited error |
| 301602 | Server error | no snapshot; provider unavailable |

**Symbol not found / omitted from `secu_quote`:** **UNKNOWN**. M1 must treat missing symbol as **no snapshot** (already Engine behavior).

**Suspended:** `trade_status` enum includes Suspension / Suspend / Halted, etc. Whether last price/volume still populate: **UNKNOWN**. M1 must not synthesize a snapshot from a previous tick. **Partial quote (push):** empty means unchanged — **do not** normalize incomplete push objects as zeros.

**Timeout:** not specified numerically. M1 must impose a **client timeout** and raise; Engine already converts that to health error.

**Malformed:** drop via `normalize_snapshot` / adapter; never reuse last snapshot.

### Futu

`ret != RET_OK` returns an error string. Subscribe-required APIs fail if not subscribed. Snapshot BMP cap 20. Exact strings for unknown symbol: **UNKNOWN**.

`suspension: bool` is official.

### Tushare

HTTP/SDK errors and empty DataFrame: **UNKNOWN** beyond “no rows”. Empty result → no snapshot.

## 20. Recommendation reasons (M0 ranking)

Ordered as required:

1. **MarketSnapshot semantics** — Pull quote exposes last, prev_close, open, high, low, volume, turnover, timestamp in one object. Push even documents cumulative vs increment. Closest official match to a snapshot. Residual: unit/session-reset UNKNOWN (R2/R3), to be **verified in M1**, not assumed away.
2. **Timestamp reliability** — Official “time of latest price” + Unix UTC. Not `datetime.now()`. Futu TZ is documented but epoch split across APIs. Tushare `trade_time` optional.
3. **Volume reliability** — Better than Futu (“units may differ”) and better than mixing Tushare 手/股 APIs; still not fully specified. M1 must measure before enabling VWAP.
4. **A/H coverage** — Official SH/SZ + HK on one API. Futu A-share blocked for global users. Tushare splits HK to another paid product.
5. **Rate limit for ≤10 symbols** — 10/s batch of 500 ≫ need. Tushare 50/min fails HOT.
6. **Failure semantics** — Documented rate-limit and server codes; Engine already omits snapshots. Suspend enum exists.
7. **Testability** — Official JSON example can be recorded. SDK is heavier to mock than Tushare HTTP, but Futu requires OpenD in every live test.
8. **Credential complexity** — Env vars documented; no local GUI daemon. Token refresh is extra work vs Tushare static token, still simpler than OpenD login.
9. **Implementation complexity** — SDK wrap + symbol pad vs OpenD sidecar vs two Tushare products + bar-vs-tick mismatch.

“Easiest HTTP” would be Tushare `rt_k`. It **loses** on (1)(2)(5) and HK.
